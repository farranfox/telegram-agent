## Первый промпт (Промпт генерации спецификации)

Напиши спецификацию на английском языке для конкретной задачи, описание которой будет ниже. Спецификацию сохрани в файл SPEC.md в корне проекта. Спецификация будет использована агентом для реализации задачи.

### Описание задачи

Разработать простейшего Telegram бота интегрированного с API языковой модели. Данный бот в будущем будет простым AI-агентом.

#### Требование к функционалу

- Бот должен принимать текстовое сообщение от пользователя в Telegram.
- Отправлять этот текст в качестве запроса в API нейросети.
- Возвращать ответ модели обратно пользователю в чат Telegram.
- Бот работает по схеме `User Message → LLM → Bot Reply`.
- На этом этапе **сохранять историю диалога не нужно**: каждое новое сообщение обрабатывается как независимый одноразовый запрос.

#### Требование к технологическому стеку

- Языки: TypeScript/JavaScript (NodeJS).
- Библиотеки: для взаимодействия с Telegram [telegraf](https://github.com/telegraf/telegraf), для тестов [vitest](https://vitest.dev/), [openai](https://www.npmjs.com/package/openai), [winston](https://www.npmjs.com/package/winston)

#### Требование к архитектуре и подходам к разработке

- Используй TDD.
- Проект должен быть модульным.
- Проект должен поддерживать разные инференсы, такие как ollama(llama.cpp), vLLM, а также проприетарные модели от таких компаний как Anthropic, OpenAI, z.ai и так далее.
- Проект содержит единую точку входа `main()` в файле `main.ts`. Функция `main()` постоянно опрашивает Telegram бота о новых сообщениях.
- При запуске программы в `main()` регистрируется обработчик, который принимает пользовательский промпт от Telegram бота и обрабатывает его.
- Обработчик ничего не знает ни о модели, которую вызывает ни о инференсе которая используется в данный момент времени, так как использует контракты(интерфейсы).
- Контракт для общения с моделью должен быть OpenAI-совместимый. Первая версия бота - простой чат бот, потом он будет простым агентом с циклом.
- Для общения с моделями используй библиотеку [openai](https://www.npmjs.com/package/openai). Используй пока `Chat Completions API`.
- Обработчки возвращает ответ от LLM, который нужно отправить назад в бот пользователю.
- Проект должен использовать `.env.example` с переменной TELEGRAM_BOT_TOKEN
- Так же в `.env.example` должны быть: `LLM_PROVIDER`(имя провайдера), `LLM_BASE_URL`( URL провайдера куда будет уходить запрос), `LLM_MODEL`(имя модели), `LOG_LEVEL`(для логгера).
- Все переменные окружения читаются при запуске и используются для настройки сторонних библиотек, реализаций контрактов и так далее.
- Файлы должны быть в Camel case как и имена классов, интерфейсов, типов, преречислений, методов и так далее.
- Имя теста должно быть такое же как и имя тестируемого файла класса с приставкой spec.
- Также должен быть `LoggerInterface`, Реализация должна использовать библиотеку `winston`, а в качестве транспорта пусть будет пока `Console`.
- Инстанс логгера создается при запуске в `main()` и используется в самом `main()`прокидывается в обработчик и другие сервисы при необходимости.
- Сообщение от Telegram нужно валидировать, проверять наличие `chatId`, а также проверять сам текст сообщения. Текст не должен пустым, он должен иметь минимум 1 символ, максимум 1024. При невалидных данных отправляется сообщение об этом обратно в бот пользователю.
- Также должен быть небольшой системный промпт, в котором должны быть прописаны некоторые правила для модели, например первое правило: модель должна уместить свой ответ в 1024 символа.

#### Пример .env

```env
LOG_LEVEL="debug"
LLM_MODEL="llama3.2"
LLM_PROVIDER="ollama"
LLM_BASE_URL="http://127.0.0.1:11434"
TELEGRAM_BOT_TOKEN=""
```
